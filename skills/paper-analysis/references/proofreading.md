# 日本語の校正（予算の上限つき）

docs-rulesスキル（https://github.com/knk1313/docs-rules）のルールで、原稿の日本語を校正する。docs-rulesの手順をそのまま使うと、ルールのファイル（約10万字）とAIによる評価で数万トークンを使う。論文分析では校正は仕上げの工程なので、次の段階に分け、上限を超えない範囲だけを行う。

## 上限

| 項目 | 既定値 | 変え方 |
| --- | --- | --- |
| 書き直しに渡す違反の数 | 30件 | `proof.py --max <件数>` |
| 書き直しの回数 | 1回 | 利用者が「校正を繰り返して」と頼んだときだけ、最大3回まで |
| AIによる評価 | 行わない | 利用者が「しっかり校正して」「AIでも校正して」と頼んだときだけ行う |
| AIによる評価の費用 | 0.50ドルまで | 環境変数 `PAPER_ANALYSIS_PROOF_BUDGET_USD`、または利用者が指定した金額 |

利用者が「校正はいらない」「急いで」と言ったときは、校正を飛ばし、報告にそのことを書く。

## 段階1：機械の採点（既定で行う）

```bash
python3 <スキルのディレクトリ>/scripts/proof.py <作業フォルダー>/report.md --save <作業フォルダー>/score-1.json
```

- `proof.py` は、docs-rulesの `evaluators/score.mjs` を探して実行し、違反を最大30件だけ、1件1行で出す。採点結果の全体（ルールの一覧など、長い部分）は `--save` のファイルにだけ書き、会話には出さない
- 原文の引用（`原文：` の行と `>` の行）と、根拠の場所（`〔…〕`）への指摘は、直してはいけないので除いてある
- 終了コード3は、docs-rulesかNode.jsがない。校正を飛ばし、報告に「docs-rulesが見つからないため校正を省いた」と書く
- `score.mjs` の場所が見つからないときは、`--score <パス>` か環境変数 `DOCS_RULES_SCORE` で渡せる

## 段階2：書き直し（既定で1回）

段階1で出た違反だけを直す。

- `→` の後に直し方の候補（`「A」→「B」`）があれば、それに従う
- 直し方が分からない違反だけ、docs-rulesの `rules/` から該当するルールIDの節を検索して読む（`grep -n -A 12 "<ルールID>" <docs-rulesのディレクトリ>/rules/*.md`）。ルールのファイルを丸ごと読まない。トークンを使う主な原因になるため
- 事実の内容（数値、固有名詞、根拠の場所、原文の引用）は変えない。直すと意味が変わる違反は直さず、残った違反として報告する
- 書き直した後に `proof.py` をもう一度実行し、`--save <作業フォルダー>/score-2.json` に保存する。違反の数の変化を報告に使う

書き直しの後は、必ず `check_quotes.py` を実行し直す。

## 段階3：AIによる評価（頼まれたときだけ）

docs-rulesの `prompts/evaluate.md` の手順で評価する。費用の上限をかけるため、別のプロセスで動かす。

```bash
claude -p --model sonnet --max-budget-usd "${PAPER_ANALYSIS_PROOF_BUDGET_USD:-0.50}" \
  --allowedTools "Read,Grep,Glob" \
  "docs-rulesスキルの prompts/evaluate.md の手順で、<作業フォルダー>/report.md を評価し、違反をJSONで返して。\
   ただし、原文の引用（「原文：」の行と「>」の行）と〔〕の中は対象外。docs-rulesのディレクトリ：<docs-rulesのディレクトリ>" \
  > <作業フォルダー>/ai-eval.json
```

- `claude` のコマンドがない環境（claude.aiなど）では、サブエージェントに同じ依頼を渡す。その場合は費用の上限を強制できないため、依頼の文に「rules/ のうち notation.md、grammar.md、forbidden-words.md だけを読む」と範囲を絞り、報告に「上限を強制できなかった」と書く
- 上限に達して途中で止まったときは、得られた違反だけを使い、報告にそのことを書く
- 評価で出た違反は、段階2と同じやり方で1回だけ書き直す。評価は繰り返さない。結果が実行ごとに揺れ、費用が増えるだけになりやすいため

## 報告の書き方

```text
校正：機械の採点で違反18件 → 書き直し1回で残り2件（NOT-016「ヶ」は固有名詞のため残した、ほか1件）
```

AIによる評価を行ったときは、使った上限の金額と、上限に達したかどうかも書く。
